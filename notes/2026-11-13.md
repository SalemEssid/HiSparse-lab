# 2026-11-13 · Day 4 · Phase 2 (Traces) → G2

G2: Quest coverage vs exact top-k measured.

## What was built

- `trace/quest.py`: Quest page summaries (incremental min/max per 16-token page), per-head upper bounds with GQA mapping, one shared ranking per layer (sink page, newest page, then head-averaged scores), and the coverage math.
- `trace/collect.py`: dense decoding with a logging attention function registered through transformers' `AttentionInterface`. Logging never changes the computation (tested). It writes one `.npz` per request with the **top 256 pages per step and layer in rank order**, so any k ≤ 256 is a prefix.
- Coverage is sampled every 50 steps at all 36 layers. Five rules are compared at k = 32, 64, 128, 256 pages: Quest shared (mean logit, the logged one), Quest shared (mean softmax), Quest per head, best shared pages (oracle), exact top-(16k) tokens per head.
- Design choices (assumptions): Workload A uses LongBench v2 with the 0-shot prompt, middle-truncated to 32,000 tokens, in **Qwen3 thinking mode** so decode runs ~1,000 natural steps (HiSparse's GLM-5.1 trace is also reasoning output). Sampling uses Qwen3's thinking settings (T = 0.6, top-k 20, top-p 0.95) with a fixed seed, because greedy decoding in thinking mode tends to loop, which would inflate locality.

## Interpretation

1. **Quest is a good enough selector for this study.** At k = 128 it captures 92.9% of the attention mass. The loss splits into two parts. Going from exact tokens to pages shared by all heads costs 3.5 points (98.1 → 94.6). Quest's estimate of which pages are best costs 1.7 more (94.6 → 92.9).
2. **Sharing one selection across heads costs nothing here, which was a surprise.** *Hypothesis:* the upper bound is a noisy estimate for any single head, and averaging 32 heads cancels much of that noise while the heads largely agree on which pages matter. Consequence: HiSparse's one-cache-per-layer interface loses no selection quality, and `mean_logit` stays the aggregation.
3. **Layers 0–2 are the weak spot (75–82%).** Their attention is spread broadly. *To verify:* the Quest authors also keep the first two layers dense for this reason. Phase 3 should simulate all 36 layers but report layers 0–2 separately.
4. **Locality is high, and higher than in HiSparse's trace.** 88.9% overlap means a cache holding only the last selection (B = k) would miss about 11% of pages. HiSparse measured 30% at B = k. This fits the operating-point concern: our k / context ratio is 6.4% against HiSparse's 2.0%. LRU at B = 2k will miss even less, which leaves less absolute room for allocation gains. Simulating k = 32, which matches HiSparse's ratio, is free from this trace because the top 256 were logged.
5. **Early signal for H1.** The B = k miss rate per layer ranges from 4.9% (layer 3) to 21.1% (layer 33), a 4× spread, with the worst locality in late layers. That is encouraging, but the decision depends on the slope of the miss curves near B = 2k and on the cold-miss share, which Phase 3 measures.
6. **Prompt quality.** Item 0 kept only 11% of its 284K-token context. The remaining Workload A traces should use items whose context fits with little truncation.

## Quality check: does Quest's selection loss hurt the model?

Question raised by Salem: the ~7% of attention Quest leaves out could change the model's output and spread through layers and steps. `trace/sparse_check.py` runs true sparse attention (each layer reads only its k selected pages at decode; prefill full) and compares it with full attention: passphrase at 5 depths of a 32K text, and teacher-forced next-token comparison on the 7 Workload A traces (400 steps each). Configurations: full; k = 128 and k = 32, each with all layers sparse and with layers 0–1 kept full. This does not affect the research question (cache size never changes outputs); it tests how realistic the traces are.
