## Predictions (written before running; draft by Claude, edit before the run)

GPU identified on Nov 12, before any measurement ran: **NVIDIA A40-24Q**, a 24 GB time-sliced vGPU profile on a 48 GB A40 (Ampere, sm 8.6, PCIe 4.0 ×16, 696 GB/s GDDR6). Driver 535 branch (CUDA 12.2), torch 2.6.0+cu124. The predictions below were refined with this, still before running.

| Measurement | Prediction | Reasoning |
| --- | --- | --- |
| H2D pinned, ≥ 64 MiB | 20–26 GB/s; lower and noisier if the vGPU host throttles or another VM on the same A40 is busy | ~80% of PCIe 4.0 ×16 peak |
| SDPA backends | flash and efficient both usable | sm 8.6 is supported by PyTorch's FlashAttention-2 kernel |
| H2D pageable, ≥ 64 MiB | 40–70% of pinned | extra copy through a driver staging buffer |
| 4 KiB per-unit `loop` copies | < 1 GB/s | ~5–10 µs per copy launch from Python dominates a 4 KiB transfer |
| 64 KiB per-unit `loop` copies | 3–8 GB/s | the same launch cost amortized over 16× more bytes |
| `stage` (CPU gather + one copy), 128 pages | 4–8 GB/s | the CPU gather (~1 ms for 8 MiB of random rows) costs more than the PCIe copy |
| Qwen3-4B config | 36 layers, 8 KV heads, head dim 128 → 144 KiB/token, 64 KiB per page per layer | project notes §6.2 |
| Qwen3-4B, 32K, one-shot prefill | fits: ~8 GiB weights + 4.4 GiB KV + 2–3 GiB activations ≈ 15–16 GiB peak | |
| Qwen3-4B TPOT (HF eager) | 8K: 20–35 ms; 32K: 25–45 ms | Floor from reading weights + KV at 696 GB/s: ~13 ms at 8K, ~18 ms at 32K; HF eager Python overhead adds 10–20 ms; time-slicing with another VM could double it |
| Needle at 32K | found | 32,000 + 128 tokens is inside Qwen3's native 32,768 context |
| Qwen3-8B at 32K (optional) | OOM in one-shot prefill; borderline with 4K chunks | 16.4 GB weights + 4.7 GB KV leave < 3 GB |
